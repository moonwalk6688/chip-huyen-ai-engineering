# 方法与心智模型

以下为基于书中方法的实践化整理。回答时先读对应章，并区分书中案例与本技能建议。

## 1. 评价驱动开发

**触发**：选模型、改提示、决定是否上线、判断新版本是否更好。

**步骤**：定义用户任务和业务门槛 → 收集真实分布与失败案例 → 按质量、安全、成本、延迟设评分规则 → 建开发/验证/保留集 → 比较基线与新方案 → 上线后将真实失败回流。

**反模式**：只看排行榜或单次演示，把模型评委分数当绝对真相，数据泄漏后还宣称提升。详见[第3章](chapters/ch03.md)、[第4章](chapters/ch04.md)。

## 2. 按失败原因选 Prompt、RAG、Agent、微调

**触发**：回答不对、格式不稳、缺知识、需要执行任务。

**步骤**：先分类失败；指令与输出约束不清，试提示和示例；缺外部或时变事实，试检索；需多步搜集信息或工具动作，设计有权限和恢复的 Agent；稳定行为/格式难以由提示解决且有高质量样本，比较微调。每一步用同一评价集检验收益和新风险。

**反模式**：拿微调当实时数据库，或给只需回答的问题无条件接写工具。详见[第5章](chapters/ch05.md)、[第6章](chapters/ch06.md)、[第7章](chapters/ch07.md)。

## 3. 数据三角：质量、覆盖、数量

**触发**：构建训练或评价数据集。

**步骤**：从目标行为反推数据类型；检查相关性、事实、标注一致性、格式、许可；覆盖真实用户差异与稀有失败；从小样本和数据量曲线估计追加数据价值；合成数据先验证再混入。

**反模式**：只追求规模、把合成样本当无误真值、忽略训练/测试重复。详见[第8章](chapters/ch08.md)。

## 4. 成本和延迟诊断

**触发**：模型太慢或太贵。

**步骤**：分离 TTFT、TPOT、端到端时间及 p95/p99；测输入/输出分布、并发、goodput 与每完成任务成本；定位算力、带宽、容量、队列或网络瓶颈；按实测比较缓存、batch、量化、副本、并行或换模型；回归质量。

**反模式**：以 GPU 忙碌率或 tokens/s 单项指标宣布优化成功。详见[第9章](chapters/ch09.md)。

## 5. 渐进架构与反馈闭环

**触发**：单模型原型进入生产或希望持续改进。

**步骤**：最小可测闭环 → 按需添加上下文、护栏、路由/网关、缓存、动作 → 为每层加权限、日志和 trace → 让用户能纠错、编辑、转人工 → 解释反馈用途并经授权采集 → 复核偏差后回填评价集。

**反模式**：缓存跨用户内容、先上复杂编排再找任务、把点击/重新生成直接当正确标签。详见[第10章](chapters/ch10.md)。
