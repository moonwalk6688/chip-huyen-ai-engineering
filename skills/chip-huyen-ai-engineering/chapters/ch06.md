## RAG：按问题构建上下文

任务需要指令，也需要该问题的相关事实。**RAG** 先从外部资料检索，再把结果交给生成模型。外部资料可来自企业文档、历史会话、数据库或互联网。长上下文不自动消除检索需求：资料可超过窗口，长输入可能定位不准，额外 token 也花钱耗时。RAG 的基本两组件是 **retriever** 与 **generator**；检索器做索引和查询，生成器依据返回片段作答。分块、索引、拼接和答案生成各自会出错，需分别评价。

**词项检索** 根据词频和逆文档频率等排序，倒排索引可快速从词定位文档；BM25 还考虑文档长度，是强基线。**向量检索** 先把文档和查询用相容的 embedding 模型映射到向量，再取近邻；能捕捉词面不同的语义，却可能模糊产品名、错误码等精确字符。大数据集通常用 ANN 近似近邻，LSH、HNSW、IVF、产品量化、Annoy 等在建索引时间、内存、召回和查询速度间取舍。书中算法与工具名是理解选型的线索，不是现行性能排名。

检索评估区分 **context precision**（取回片段中相关的比例）与 **context recall**（所有相关片段中取回的比例）；后者要知道没取回的相关文档，现实中较难标注。若位置重要，可看 NDCG、MAP、MRR。向量模型需单独测相似度及目标任务效果，最终还要测答案的正确性、来源支持度、时延与成本。向量库的嵌入生成、存储、更新和查询均有成本，数据频繁变化时尤需核算。

**Hybrid search** 结合词项与语义检索，可先粗召回后重排，或并行召回再融合排序。RRF 以各检索器中的名次融合，书中公式有平滑常数；其价值是融合不同排序，不保证每个任务都改善。优化包括：

- **分块**：固定字符/词/句/段、递归按结构拆、按代码语法或问答对拆；边界重叠可减少信息割裂。小块有更多覆盖，可能失上下文并增加向量数；大块可能检索不准。按目标模型 token 切分方便预算，但换 tokenizer 可能重建索引。
- **重排**：用更精细方法或时间新鲜度调整候选；评估重排对答案而非仅对检索分数的影响。
- **查询改写**：把“Emily 呢？”结合前文改成独立问题；未知身份时保留不确定性，不能捏造。
- **上下文化检索**：给块补标题、摘要、关键词、实体、可能回答的问题或整篇文档中的位置说明，再索引；检查自动生成的说明是否忠实。

多模态 RAG 可按标题/说明或共享嵌入检索图像、音频、视频。表格问题通常需要选表、生成受限 SQL、执行、再据结果生成答案，不能把整表当普通文档检索；书中 SQL 样例 OCR 不完整。

## Agent：环境、工具与规划

作者借用“能感知环境并在其中行动”的宽定义。Agent 的能力由任务环境、可用工具、规划模型决定；书中把使用检索器的 RAG 也视为简单 Agent，同时提醒当时 Agent 理论和评价仍在发展。工具可用于 **获取知识**（文档、网页、邮件、数据库）、**扩展能力**（计算器、解释器、转写、图像生成）或 **写入环境**（更新数据库、发邮件、付款）。读写权限应区分；工具越多能力越广，也更难选择、理解和保护。多步任务有复合错误：书中以单步 95% 成功率的独立近似说明十步/百步成功率快速下降，实际流程要测依赖关系和恢复机制。

规划应写明目标与约束，选择可执行且有效率的动作。可先生成计划、验证有效工具/约束/步数，再执行并根据工具反馈调整；计划不必一次覆盖全程。人可提供高层计划、验证高风险步骤或亲自执行。自然语言高层计划比写死函数名易迁移，但需可靠地翻译成具体调用。顺序、并行、条件和循环是不同控制流；框架要按任务验证是否支持。函数调用的**工具名合法、参数模式合法、参数值正确**是三种不同检查，API 的结构约束也不能证明参数语义正确。记录每次调用及其输入输出。

作者讨论模型能否真正规划的争论，结论不是简单的是或否。可用搜索、状态追踪、预测动作结果、回溯、分层规划与反思补强。ReAct 交替规划、行动、观察；Reflexion 对失败结果评估并重试。反思可在请求开始、计划后、每步后和结束时进行，但增加 token、成本和时延。工具清单应通过消融实验、错误统计、调用分布来优化；频繁失败的工具可简化接口或替换。

Agent 评估要覆盖 **规划失败**（不存在的工具、错误参数、目标/预算/截止时间未满足、误以为已完成）、**工具失败**（正确调用却返回错结果、缺工具、翻译层出错）和 **效率失败**（过多步骤、费用、耗时）。评价集包含任务和可用工具，记录计划有效率、达到有效计划所需次数、各类调用错误率、最终任务完成率。工具独立测试，终局任务与人或基线流程比较。对写操作设权限、可回滚设计与必要的人类批准；这对应本书的安全讨论，实际授权依用户和应用规则执行。

## 记忆

书中分模型权重中的 **内部知识**、当前输入中的 **短期记忆**、可检索外部库中的 **长期记忆**。短期空间有限，长会话需要决定保留、压缩、迁出什么。FIFO 容易实现，却可能丢掉开头的目标和约束；摘要、实体追踪、去冗余和对新旧矛盾的判断更稳健，但摘要本身也可能漏关键信息。长期记忆可跨会话保存偏好、历史、结构化状态，检索机制类似 RAG。哪些信息进入权重、当前上下文或外部库，应按使用频率、更新需求和敏感性决定；不要把旧信息覆盖新信息的规则写成无条件真理。

## 项目检查单（本 Skill 整理）

1. 为真实问答构造可追溯资料集，标注相关片段与应有答案。
2. 从 BM25 和最简单生成流程建基线，再比较向量、混合、重排、改写与分块。
3. 同时报告检索召回/精度、答案正确与证据支持、P90 时延、索引和查询成本。
4. 给 Agent 列明环境、工具权限、计划验证、停止条件、失败恢复与人工接管点。
5. 记录每步工具参数和结果；对长会话测试摘要丢失、事实更新和跨会话记忆偏差。
