# 第 2 章：Understanding Foundation Models

**来源**：用户提供的 OCR Markdown 第 1445—2680 行，含章末注释。图像只有标题、周边文字与部分 OCR 表格可核对。模型、API、价格、研究结论均保留原书写作时的时间背景。

## 训练数据决定能力分布

作者从训练数据、架构和规模、后训练、采样四组决策解释基础模型。通用语料让模型覆盖大量任务，但不能推出它在目标行业、语言或地区可靠。Common Crawl 等网页语料规模大，质量参差；清洗和筛选会改变主题与语言分布。书中 C4 的领域分布是特定语料的观察，不是全部模型的训练分布。判断候选模型时，应查看目标任务的语言、知识类型、文化背景与语料可能存在的偏差；不能仅凭总参数或基准总分替代本地评测。

多语言模型的语言覆盖并不均匀，低资源语言可能因训练数据和 tokenization 获得较差质量、更长 token 序列与更高调用成本。作者给出了英语以外的问题、翻译和数学题等例子，提醒不要把英语成绩直接迁移到中文场景。领域模型可以通过选择训练数据、继续训练或应用侧适配改善特定任务，但领域名称本身不保证性能。这里的语料分析和示例属于原书时期的情况；现有模型应重新核验。

## 架构、规模和算力

循环网络按顺序处理序列，长距离依赖和梯度传递是挑战。seq2seq 的注意力允许解码时关注输入的不同位置。Transformer 用自注意力、Q/K/V 与位置表征建立 token 间关系，使输入阶段较易并行；生成阶段仍逐 token 解码，长上下文的注意力计算与 KV cache 带来内存和时延问题。书中图解了 prefill、decode、注意力模块和 transformer block。理解这些结构的实际用途是解释为何长提示影响首 token 时延、为何长输出影响总时延、为何上下文不是免费无限扩大。作者也提及 RWKV、状态空间模型、Mamba、Jamba 等替代或混合架构；它们是研究和产品实例，不构成永久排名。

模型“大小”至少分清参数量、训练 token 数与训练 FLOPs；FLOPs 是计算工作量，FLOP/s 是设备速度。稠密模型的参数基本都参与一次计算，稀疏 MoE 模型的总参数量与每 token 激活参数量不同，不能只比较总参数。更多数据与参数通常改善能力，但训练算力、推理费用与数据质量共同约束选择。书中讨论 Chinchilla 一类 compute-optimal scaling：在特定预算和假设下平衡模型大小与训练 token，约 20 token/参数是研究中的经验量级，不是所有模型的工程定律。训练最优和部署最优也不同：更小模型训练更久，可能换来较低推理成本。书中 H100 租金等数字是历史例子，不作为当前报价。

## 后训练和“符合偏好”

预训练主要学习语料中的模式，未必形成有用、安全、遵循指令的助手。作者把后训练拆为 **SFT**（示范响应的监督微调）和 **preference finetuning**（从偏好数据调整输出），介绍排序/成对比较、奖励模型、RLHF、DPO 等路径。示范与偏好数据的来源、标注员背景和指令会塑造模型行为；人类偏好不唯一，单个奖励函数难完整表达。不要把“经过 RLHF”视为事实准确性的保证。OCR 中奖励模型损失公式括号残缺，概念可核对，精确数学表达不能据此复述。

## 采样与输出控制

语言模型输出 logits，经 softmax 转为 token 概率。**greedy decoding** 每步取概率最大项；随机采样能提供多样性，但也带来同一输入的不同响应。温度改变概率分布的集中程度；top-k 保留固定数量候选，top-p 保留累计概率质量达到阈值的候选，min-p 根据相对概率截断。停止 token、最大输出长度等决定生成何时终止。参数值没有跨任务的普适“最佳”设置，应记录模型版本与所有采样参数，使用真实任务集比较质量、稳定性、时延和成本。固定随机种子仍不能保证跨硬件、服务实现和版本完全一致。

作者讨论 **test-time compute**：为同一问题生成多个候选，再通过评分器、验证器或 self-consistency 选择或聚合。它可提高一些任务的成功率，但消耗额外推理成本；选择器自身也可能出错。结构化输出可用提示、后处理、重试、约束解码或微调实现。**格式合法不代表内容正确**，JSON 可解析也不等于字段值可信。书中 API 参数与服务能力是写作时的实例，应用时查当前官方文档。

## 不一致与幻觉

作者区分两类不一致：完全相同的输入得到不同输出，微小输入变化引发大幅输出变化。缓存相同请求、固定温度/top-p/top-k/seed 可减轻前者；后者还需要稳健提示、上下文设计、评价与产品约束。书中的作文打分例子显示评分不稳定，图像本身未取得；不能把例子当作某个当前模型的稳定性能指标。

“幻觉”是需要事实性的任务中的核心失败模式。作者呈现两种互补**假说**，不是已经证实的唯一成因：其一，模型把自己刚生成的错误内容继续当条件，错误会滚雪球；其二，监督数据中的答案可能依赖标注员知道而模型不知道的知识，促使模型模仿出似是而非的回答。书中引用 InstructGPT 对不同数据集的结果说明偏好优化可能改善总体偏好、却在某一幻觉指标上劣于只做 SFT 的模型；不能概括为“RLHF 必然减少幻觉”或“必然增加幻觉”。检索来源、要求承认未知、简短回答、验证器、评价管线等可帮助控制风险，但不能保证消灭幻觉。

## 用于项目的决策流程（本 Skill 整理）

1. 抽取真实任务样本，按语言、领域、所需事实、允许错误率和输出格式分层。
2. 比较候选模型的质量、上下文长度、TTFT/总时延、推理成本与数据边界；区分总参数和激活参数。
3. 固定模型版本与采样设置，再测同问多次和轻微改写，记录方差。
4. 对事实性任务单独设置来源核验、未知回答和人工复核门槛；格式校验之外还验语义。
5. 若考虑微调，先明确数据缺口与标签标准，再比较提示、检索、后训练的投入产出。
